# 自动完整扫描：第一版开发计划

计划制定日期：America/Phoenix 2026-10-05，当时基线应用 0.0.6、API 1.1.0、profile v3。该计划的代码交付已在 **0.0.7 / API 1.2 / profile v4** 完成；2026-10-07 两平台 CI、native fixture 与安装检查通过。[实际设计/结果](../ci-validation/auto-full-scan-v1.md) · [当前剩余工作](REMAINING_WORK.md)

当前仅保留真实 GUI/硬件恢复/用户数据升级等验收项（T1–T3）；不能把下文实施顺序和新会话开发 prompt 当作尚未实现的任务再做一遍。

## 1. 交付目标与范围

在软件运行期间，用户启用自动采集后，系统自动检查已启用来源；发现来源变化时，调用现有完整扫描，并自动更新界面。最小化仍工作，退出时停止。电脑休眠恢复后检查一次，不补跑休眠期间错过的每个周期。

本阶段交付：设置开关和间隔、轻量变化检测、统一调度器、事件合并、休眠恢复、取消与失败处理、前端后台扫描状态和缓存刷新。

本阶段继续生成完整 Daily/Session 快照。三个 Adapter 的 `supportsIncrementalCollection` 仍为 false；不实现文件读取游标、事件级去重、增量累加或多设备同步，不改价格、token 口径、数据集身份及完整快照替换规则。

## 2. 用户界面与配置

- Settings 增加“自动采集 / Automatic collection”开关，默认关闭。
- 间隔提供 1、5、15 分钟，默认 5 分钟；保存到宿主配置，重启后保留。
- 文案明确：定时检查来源，有变化时完整扫描；只统计已启用来源，软件关闭后不继续运行。
- 显示自动采集启用状态、检查/扫描状态，以及可获得的最近成功时间和下一次检查时间。使用当前统计时区与所选界面语言。
- 自动任务可取消；关闭自动采集后停止新任务入队，清除待执行的自动请求。明确当前自动任务是否同时取消，并与 UI 文案一致；推荐取消尚未提交的自动任务，保留已提交结果。
- 用户手动扫描继续可用。关闭自动采集不能取消不属于调度器的手动任务。
- 沿用设置版本检查、目录不透明引用与源配置写入门禁。来源目录/时区不能在活动扫描中被无保护替换。自动开关/间隔若允许扫描中保存，应独立校验，不能顺带绕过来源配置门禁。
- 所有新增静态文案、提示、错误和可访问性标签提供中文/英文；默认中文。

## 4. 轻量变化检测

1. 仅检查已启用来源和用户配置的目录，范围与现有 Adapter 相同；不扫描整个磁盘，不读取认证文件，不把路径或正文发送到前端或远端。
2. JSONL 来源检查纳入范围的文件集合、文件身份/替换、大小和修改时间；包括新增、移除、改名、截断或历史文件修正。不要只比较目录本身的修改时间或最后一条消息时间。
3. Antigravity 检查已支持的 `.db` 及对应 `-wal`；数据库的新内容可能仍在 WAL 中。忽略读取/锁状态等无关噪声，`.pb` 仍按现有不支持边界处理。
4. 变化检测放在 Adapter/原生层。遵守 Core 定义端口、Adapter 实现 IO 的依赖方向，避免宿主复制另一套目录发现规则。具体新增端口或扩展方法在设计小结中说明。
5. 指纹作用域必须区分 Provider、dataset、来源目录、统计时区及影响归一化的版本。时区/来源范围改变后，旧指纹不能用来跳过新范围的采集；界面语言变化不触发扫描。
6. 首次启用、启动时缺少可信成功基线，应进行一次完整扫描。不能仅把当前文件状态设为基线，然后永远跳过可能过期的缓存。
7. 只在扫描成功提交后推进成功基线。保留开始扫描前的指纹；扫描期间发生变化时保持 dirty，之后再检查，不能把完成时的所有新变化当成已采集。
8. 元数据指纹是轻量检查。真实内容修改事件、监听丢失/溢出或无法确认的状态不能被“指纹没变”静默吞掉，应保守复核。过滤单纯访问事件以及采集器自己的临时输出，避免自触发循环。

第一版可以使用内存基线并在每次启用/启动后保守重扫一次。若持久化指纹，必须与成功扫描和作用域绑定；失败或进程退出后宁可多扫一次，不能跳过未提交的数据。

## 5. 统一调度器与生命周期

建议新增宿主 `scheduler.rs`，调度政策与实际扫描执行分开，方便合成测试。不要在 React 中放完整扫描定时器，不增加独立后台服务。

事件入口：间隔到期、有效日志变化、休眠恢复、启用自动采集、来源/时区配置变更。所有入口使用同一队列；手动扫描继续走已有入口，与自动任务共用 Runtime 的来源互斥。

调度顺序：

```text
收到请求
  → 自动采集开启且来源已启用？
  → 合并同一来源的短时间请求
  → 检查作用域与来源状态
  → 有变化 / 尚无可信基线？
  → 满足扫描间隔与重试冷却，且没有同来源活动任务？
  → Runtime::start_scan（现有完整扫描）
  → 成功：更新成功基线，通知前端
    失败：保留旧快照与基线，退避重试
    取消：保留旧快照与基线，等下一轮检查或用户主动扫描
```

必须满足：

- 短时间请求合并可从 2 秒开始，但另有扫描间隔限流；文件持续写入不能导致每 2 秒完整扫描。
- 同来源最多一个活动任务、一个待检查状态。自动任务建议全局串行，降低多个全量扫描同时发生的资源占用。
- 活动扫描期间收到新变化，只标记 dirty；结束后按间隔再次检查，不积累无限任务。
- 手动扫描优先，保持已有合并/取消行为。不能把加入一个已经开始的手动任务时观察到的指纹直接当作该任务完整输入基线。
- 调度去抖、间隔和退避使用单调时间；展示时间使用 UTC 时间戳按统计时区格式化。测试使用可控时间，不真实等待几分钟。
- Tokio 周期计时避免补跑错过的 ticks；恢复后合并为一次检查。实现原生恢复信号或可靠的时间跨度检测，并记录两平台实际验证方式。
- 故障、超时、目录缺失或不完整覆盖沿用现有错误/历史保留规则，不显示伪造零值。自动与手动对相同输入生成相同统计结果。
- 取消后不立刻因 dirty 自动重启；失败使用有上限的退避，不形成重试忙循环。
- 退出先停止定时器、监听和新任务入队，再沿用 Runtime 退出回收；不恢复上一进程未完成的任务为隐式继续运行。
- OS 文件监听不可用时有间隔检查后备；事件只提示来源可能变化，不能冒充增量解析。

## 6. 前端、接口与兼容

- 配置/状态接口按能力协商启用；旧配置有默认值，旧服务缺少能力时 UI 明确不可用，不发送其不认识的新参数。
- 若扩展 API/profile，说明兼容方式并更新契约、生成类型、版本检查和持久化迁移。保留 deviceId、datasetId 及现有历史。
- transport 封装 Tauri 事件订阅与取消订阅。启动时获取状态；事件通知和轮询都通过同一 UsageClient 能力抽象，Mock 有对应合成行为。
- 开始/结束扫描时刷新来源状态与查询缓存；界面最小化或错过事件后恢复时重新获取当前状态。避免重复监听及无限缓存失效循环。
- UI 能区别自动任务与用户任务，并对有明确 job ID 的活动自动任务调用既有取消接口。
- 对“自动开关关闭”“来源关闭”“间隔改变”“时区/目录改变”和应用重启分别说明行为；设置变更影响后续调度，不能污染已开始扫描的作用域。

## 8. 原验收标准与当前证据边界

配置/迁移、调度/合并/限流/取消、metadata/WAL/监听、后台状态/刷新、语言与自动/手动一致性均已有合成和两平台 native 证据；系统真实睡眠及完整人机 UI 操作仍需 T1–T3。下面保留原标准，以便实际验收逐项对照。

- 新/旧配置自动采集默认关闭，默认间隔 5 分钟；只有 1、5、15 可选，非法值拒绝；设置重启后保留，身份和历史不变。
- 自动关闭或来源未启用时，调度器不监听/读取该来源并不启动自动任务；不改变现有 UI 的来源检测行为。
- 有可信基线且无变化时不启动采集；新增、追加、有效历史修正、替换/截断、数据库 WAL 变化能触发检查与完整扫描。
- 多个触发入口及一连串文件变化合并为一次扫描；持续写入遵守限流。
- 与手动扫描重叠不造成同来源并发；扫描期间又发生变化最多追加一次待检查，不丢变化。
- 失败/取消不推进成功指纹、不清空快照、不显示伪造零，不立即无限重试。
- 休眠跨过多个间隔后检查一次；退出时无残留 timer、watcher 或 sidecar。
- 后台扫描完成后无需点“刷新视图”，来源和图表显示新结果；订阅重连、关闭和重复挂载不积累监听。
- 两种语言一致；切换语言不改变自动配置、统计时区或触发采集。
- 相同合成输入的自动结果与手动完整扫描一致，包括重复扫描、修正、空/未知字段、时区与失败保留历史。
- 用现有前端/Node/Rust 测试、typecheck、lint、契约/边界/版本检查及 native fixture；CI 不依赖真实用户日志或真实分钟级等待。
- 本机缺 MSVC/SDK，不安装系统组件；原生验证使用现有 Windows/macOS CI。提交、推送、运行远程 CI、发布安装包按新会话的人类授权处理，不能把历史某次发布许可当作本次自动许可。
